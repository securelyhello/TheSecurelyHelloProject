# Website

The product page (`index.html`), the invite landing page (`i/`), and the
privacy and terms pages. It's plain static files, with no build step needed
to serve them. The site requests nothing from other hosts: no fonts, CDNs or
analytics.

## Before you deploy

1. Fill in `config.js`: store links, the APK paths (the per-CPU ones are
   optional), the certificate fingerprint, source and contact. Empty
   entries hide their buttons.
2. Point the server's `INVITE_BASE_URL` at `https://<this site>/i/`.
3. Publish a release into `download/` with `tools/release_apk.py` (APK(s)
   and `latest.json`, which the app's updater and the download section
   read). `download/` is git-ignored: copy it to the server with the site.
4. After editing `docs/legal/*.md`, rebuild the legal pages:

   ```
   python3 tools/build_site.py
   ```

## What's here

- `index.html`, `styles.css`, `early.js`, `site.js`: the product page. The
  look is the Hum theme from the Hallmark design skill (grained cream paper,
  torn sheets, Chillax, pear for the action). `styles.css` is the page,
  `tokens.css` holds every colour, size, font-face and torn-edge shape, and
  `base.css` holds the shared resets. Motion is one scroll reveal and the
  "what the server sees" noise; both stop under reduced motion.
- `assets/fonts`: Chillax (Medium and Semibold WOFF2) under the ITF Free Font
  License, which allows self-hosting but not redistribution, so the files are
  git-ignored. Fetch them with `python3 tools/fetch_fonts.py`. Never inline
  them or load them from Fontshare.
- `assets/texture`: `grain.svg` and `fibre.svg`, the paper textures, as files
  (the invite and legal pages' CSP has no `data:` images).
- `assets/icons`: the Lucide chevron (ISC licence), used as a CSS mask.
- `assets/screens`: the app screenshots from the UI test. The page shows them
  in `data-slot` frames named hero, chats, calls, calls-tab, stories, groups,
  people and get; `data-alt` says what each should show.
- `i/index.html`: the invite page. It links `/styles.css` and `/assets/...`
  with absolute paths on purpose, because it is served at `/i/<token>`.
- `privacy.html`, `terms.html`: generated by `tools/build_site.py` from
  `docs/legal/*.md`; the page template is in that script.
- `assets/logo.svg`, `favicon-32.png`, `apple-touch-icon.png`, `og.png`:
  generated by `tools/make_icons.py` from `assets/brand` (see
  `docs/BRAND.md`).
- `assets/download-qr.svg`: a QR code for the APK. To regenerate it, run
  `pip install qrcode`, then:
  `python3 -c "import qrcode, qrcode.image.svg as s; qrcode.make('https://securelyhello.thenn.in/download/securelyhello.apk', image_factory=s.SvgPathImage).save('website/assets/download-qr.svg')"`.

## Refreshing screenshots and test results

The screenshots are captured by the UI test against a real server, and
`assets/report.json` holds the latest test counts. With the dev server running
(see the main README, "Tests"):

```
MAIL_DIR=/tmp/sh_mail python3 tools/build_site.py --run-tests --with-integration
```

On a headless machine, add
`SITE_TEST_WRAPPER="xvfb-run -a dbus-run-session --"`. The script exits with
an error, and still writes the report, if any test fails.

## Serving

Serve this folder at the domain root. Two things matter:

- `/i/<token>` must serve `i/index.html`. The page reads the token from the
  path.
- Send security headers. The pages also carry a CSP meta tag, but
  `frame-ancestors` and HSTS only work as real headers.

Caddy:

```
securelyhello.example {
	root * /srv/securelyhello/website
	rewrite /i/* /i/index.html
	log_skip /i/*
	file_server
	header {
		Content-Security-Policy "default-src 'self'; img-src 'self' data:; style-src 'self'; script-src 'self'; connect-src 'self'; base-uri 'none'; form-action 'none'; frame-ancestors 'none'"
		Strict-Transport-Security "max-age=31536000; includeSubDomains"
		Referrer-Policy "no-referrer"
		X-Content-Type-Options "nosniff"
		Permissions-Policy "camera=(), microphone=(), geolocation=()"
	}
	@report path /assets/report.json
	header @report Cache-Control "no-cache"
}
```

nginx:

```
server {
    server_name securelyhello.example;
    root /srv/securelyhello/website;
    # Invite tokens are in these paths: keep them out of the logs.
    location /i/ { access_log off; try_files /i/index.html =404; }
    # expires, not add_header: add_header here would drop the headers below.
    location = /assets/report.json { expires -1; }
    add_header Content-Security-Policy "default-src 'self'; img-src 'self' data:; style-src 'self'; script-src 'self'; connect-src 'self'; base-uri 'none'; form-action 'none'; frame-ancestors 'none'" always;
    add_header Strict-Transport-Security "max-age=31536000; includeSubDomains" always;
    add_header Referrer-Policy "no-referrer" always;
    add_header X-Content-Type-Options "nosniff" always;
    add_header Permissions-Policy "camera=(), microphone=(), geolocation=()" always;
    # listen / ssl_certificate lines for your setup
}
```

Both configs keep `/i/` paths out of the access log, since they contain
invite tokens.
